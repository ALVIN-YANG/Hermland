# 准备中转服务器

VPS 是你向云厂商租用的一台服务器。Hermland 用它转接家里与外面两台 Mac 的连接，Agent、模型和会话仍留在家里。不需要域名，也不用给家里路由器开端口。

这份指南只做到“服务器准备好，能可信登录”。之后回 App 发连接卡，让原 Agent 协助部署；你也可以按[手动配置指南](快速开始.md#手动备用按六步完成同一配置)操作。不能登录、没有管理权限时先停下，不跳过身份核对。

## 1. 准备一台自己的 Debian / Ubuntu 服务器

已有合适的服务器可以复用，不必再买一台。没有时，在你信任的云厂商创建 Linux 云服务器，选择 Debian / Ubuntu。服务器费用由云厂商收取，Hermland 不代购、不托管。

在云厂商控制台记下：

- **公网 IP：** 填入 App 的「服务器地址」。不要填家里的局域网 IP。
- **SSH 端口：** 通常为 `22`，以你的实际配置为准。
- **管理员用户名与登录方式：** 由你在云厂商处设置或取得；初始化脚本需要 root 或 sudo 权限。

为 Hermland 只需允许实际使用的 SSH 入口，保留其他服务必要的防火墙规则。不要为 Hermland 开放 Agent 网页或中转端口：`8787`、`18789`、`19119`、`19121` 都不应对公网开放。不要覆盖已有服务器的其他配置；脚本遇到不兼容的 SSH 规则会停止。

**准备好的标志：** 控制台显示服务器运行中，你知道它的公网 IP、SSH 端口和管理方式。

## 2. 先核对身份，再从 Mac 登录

SSH 是 Mac 与服务器之间的加密管理连接。首次连接会询问是否信任服务器：不要仅因为出现了提示就输入 `yes`。

先在**云厂商提供的可信控制台终端**登录这台服务器，查看其 Ed25519 主机公钥指纹：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

记下输出中的 `SHA256:…` 指纹，不读取同目录中没有 `.pub` 后缀的私钥。若文件不存在或你无法确认控制台可信，找管理员协助，不改成忽略校验。

然后在管理用的 Mac 打开「终端」。下面是格式示例，先把端口、用户名和 IP 换成真实值再执行：

```bash
ssh -o HostKeyAlgorithms=ssh-ed25519 -p 22 管理员用户名@服务器公网IP
```

首次提示的指纹必须和控制台刚才看到的相同，确认一致后才接受；密码、私钥口令由你自己输入，不发给聊天 Agent。如果已保存的身份突然变化，先核实原因，不删除旧记录来绕过警告。使用已有管理员密钥时，继续沿用自己的可信 SSH 配置，不复制管理私钥到 Agent 工作区。

**准备好的标志：** 指纹一致，成功进入服务器命令行，并具有所需管理权限。退出用 `exit`。连接超时先核对 IP、端口与安全组；拒绝登录先核对用户名和你的登录凭据。

## 3. 回到 Hermland

在**外出的 Mac** 打开 Hermland，选择原来的 Agent →「开始连接」→「我有云服务器」。填公网 IP 和 SSH 端口，确认已能可信登录，再继续复制连接卡。

把卡片发到你平时与**家里的 Hermes / OpenClaw** 对话的入口。它有执行权限时协助操作；没有权限时，让它给出命令，由你或管理员在对应机器执行。App 不收管理员密码，不因填入 IP 自动登录服务器。不要授予 Agent 永久管理权限来省这一步。

接下来会按需安装中转工具、核对家里 Mac 和外出 Mac 的公钥、由你明确确认授权，最后返回 `.json` 连接文件。**公钥可以发送，私钥不能发送；连接文件不能代替设备授权。**

已有正常 Agent、隧道和其他服务都应复用，不重装、不升级、不改模型或会话。想手动完成的用户，从[快速开始](快速开始.md)按步操作，每步检查通过再继续。
