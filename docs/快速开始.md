# 快速开始

面向已经在使用 Hermes 或 OpenClaw 的用户。推荐直接把初始化指令发给你自己的 Agent，让它复用当前环境、补齐远程接入组件并逐步验证；不用另找一个编程 Agent，也不用重新安装一套大脑。自己手动执行是备用方式。

当前接入支持：已有 Hermes + Hermes WebUI，或已有 OpenClaw Gateway + 官方 Control UI；常驻 macOS 机器、Debian/Ubuntu VPS、Mac 客户端。不需要域名，不向公网开放 WebUI。两种后端使用同一套手动公钥授权与双 SSH，OpenClaw 保留自己的 Gateway 登录，不安装 Hermes 作为中间层。

## 推荐：发给你已有的 Agent

在你平时使用的 Hermes/OpenClaw 对话入口中发送下面这段，填写项目路径和已验证的 VPS 管理连接即可。不是把这段话发送到尚未连通的 Hermland。

```text
我已经在使用你，请帮我为 Hermland 初始化远程接入。项目路径：[路径]；VPS 管理连接：[已有可信 SSH 连接，或由我手动执行管理命令]。先阅读项目 docs/快速开始.md，检查当前 Agent 类型、实际运行机器及兼容性：Hermes 使用已有 WebUI；OpenClaw 使用已有 Gateway/Control UI，全程给 check、relay-install、export 加 --backend openclaw，按实际端口和 controlUi.basePath 配置，不替我安装 Hermes。复用现有 Agent、模型、凭据、记忆和会话，只补远程接入组件，不重装、不升级、不迁移、不改模型或其他网站。使用 deploy 中的同一套脚本逐步执行，每步报告 PASS/FAIL 和不含秘密的证据，失败停在当前步骤；服务器公钥必须来自已核对的管理连接。需要常驻机或 App 公钥时，让我手动提供并核对指纹，得到我明确确认后才由管理员授权 SSH。有现成执行权限可协助执行；没有权限就给我对应的管理命令，不自行扩大权限，不复制管理私钥到 Agent 工作区，不授予 Agent 永久管理权限。不要读取或输出模型凭据、私钥、密码或 Gateway 令牌，不关闭审批、SSH 身份校验、Gateway 认证或设备身份检查，不新增公网 WebUI、SSH 主动申请或自动批准。OpenClaw 内层登录交给我在页面中完成，其上游回环配对规则不由你改写。最后导出已授权设备的连接 JSON，指导我导入 App；链路健康、Gateway 登录和真实模型回答分别验收，模型测试由我本人发送或明确批准。缺权限、兼容性或我的确认时，说明具体下一步，不声称完成。
```

你只需提供必要的非敏感信息、手动发送公钥、确认要授权的机器，最后导入 Agent 或管理员返回的 JSON。管理员可以就是你；公钥授权仍须人工确认，不能由模型自己决定。Agent 没有主机执行权限时，再按下面六步手动完成，不为初始化关闭它原有的安全审批。

## 开始前

准备已有 Agent 的常驻 Mac、一台可通过**已验证的管理员 SSH**登录的 VPS，以及 Hermland 项目目录。初始化指令让 Agent 自己检查当前机器与目录，不默认另建一台后端机器。管理员可以就是你，在 Mini 或另一台管理电脑操作。本文的 `VPS_IP` 要换成你的地址；默认 SSH 端口 22，Hermes WebUI 8787 / OpenClaw Gateway 18789、中转 19119、App 本地 19121。非默认端口见脚本 `--help`。

VPS 的云安全组需允许你使用的 SSH 端口；不要开放 8787、18789、19119 或 19121。模型凭据只留在常驻 Mac，不发给 Agent，不写进 App 配置。OpenClaw Gateway 登录凭据只在已建立可信通道后的原生登录页输入，不放进连接 JSON、初始化话术或 URL。

项目源码：[ALVIN-YANG/Hermland](https://github.com/ALVIN-YANG/Hermland)。当前是开发预览，没有正式签名/公证安装包。可以取得源码，或在 App 的「导出配置工具」中保存 `HermlandSetup.zip`，解压后使用其中的 `deploy/` 与 `docs/`。App 内「复制初始化指令」会按所选后端生成同样的指引。源代码构建见 [README](../README.md#开发与检查)，不提供未验证的 `curl | bash` 入口。

## 手动备用：按六步完成同一配置

每步通过检查后才继续；失败时修复当前步骤，不跳过验证。

## 1. 常驻 Mac：检查并复用已有 Agent

### 已有 OpenClaw

复用原来的 Gateway，不运行 `backend-install`，不重装、不新建第二个服务。通过原有启动方式确认 Gateway 正常运行，Control UI 已启用，监听仅为本机回环。可在本机查看 `openclaw config get gateway.auth.mode`，仅核对模式，不读取/输出 `gateway.auth.token`；认证关闭时停止初始化，由用户确认如何恢复认证。保留 token/password 和设备身份校验，不设置 `dangerouslyDisableDeviceAuth` 或允许来源 `*`。

```bash
python3 deploy/hermland.py check --backend openclaw
```

默认检查 `127.0.0.1:18789`，同时允许已有的 `::1` 回环监听；任何公网/LAN 监听均拒绝。如果原 Gateway 使用其他端口或 `gateway.controlUi.basePath`，显式加 `--port 实际端口 --ui-path /实际路径`。打开原 Control UI 确认还是原 Agent 和原会话。检查通过只表示 `/healthz` 存活且页面存在，不表示 Gateway 已认证或模型能回答。

后续沿用第 2–6 步，但第 3 步的 `relay-install`、第 4/6 步的 `check` 和第 5 步的 `export` 都加 `--backend openclaw`；自定义路径须在这些命令中保持同一 `--ui-path`。`relay-install` 默认后端端口 18789，非默认端口加 `--backend-port`。其余 SSH 端口与手动公钥授权不变。

### 已有 Hermes

已有正常运行的 Hermes/WebUI：直接检查，不重装、不升级、不改模型。

只有 OpenClaw：使用上面的 OpenClaw 分支，不安装 Hermes。两者都没有或后端机器不是 macOS：停止这条初始化路径，报告兼容性限制。本指引不负责安装新的 Agent，也不要求重新登录模型或输入一遍 API Key。不要在只用于连接的客户端 Mac 再安装一份后端。

没有 WebUI：在你选定的目录获取 [Hermes WebUI](https://github.com/nesquena/hermes-webui)，不要覆盖已有目录。例如在常驻 Mac 的项目目录执行：

```bash
git clone https://github.com/nesquena/hermes-webui.git hermes-webui
python3 deploy/hermland.py backend-install --webui-dir ./hermes-webui
```

此命令只登记本机回环的登录启动服务；不安装或修改 Hermes，不处理模型凭据。自定义 Hermes 数据目录可加 `--hermes-home /实际路径`。首次准备 Python 依赖可能超过检查等待时间；失败后检查本机日志，修复后重跑。已有后端会被复用，不替换原服务。

在常驻 Mac 执行：

```bash
python3 deploy/hermland.py check --port 8787
```

通过标准：打印 `PASS`，只监听 `127.0.0.1:8787`，健康接口返回 `status=ok`。再打开 `http://127.0.0.1:8787`，确认连接的是原来的 Agent 和模型、原会话可见，发一条消息确认模型有真实回答。若 WebUI 要求重新配置模型，先核对是否发现了正确的已有 Hermes 数据目录，不另建一套配置。**健康检查通过不等于模型能用。**

新建的服务是用户登录启动，不是退出登录后仍运行的系统服务。常驻 Mac 须保持用户登录、网络可用且不睡眠。已有服务请确认它也能在登录后恢复。

## 2. VPS：安装管理工具

将本项目的 `deploy` 目录传到 VPS。下面示例在管理电脑的项目目录执行；`root@VPS_IP` 必须已完成服务器身份核对，不能关闭主机公钥检查：

```bash
scp -r deploy root@VPS_IP:/root/hermland-deploy
ssh root@VPS_IP 'bash /root/hermland-deploy/setup-vps.sh'
```

通过标准：打印 `PASS`，管理员工具安装到 `/opt/hermland`，原 SSH 配置有效。此步不会授权任何设备，也不会开放公网网页端口。

若缺依赖，在 Debian/Ubuntu VPS 控制台安装 `python3 openssh-server iproute2`，确认 `ssh.service` 正常后重跑。脚本发现已有不同版本会停止，不自动覆盖；管理员核对差异后可使用 `setup-vps.sh --upgrade`，原工具会备份，不迁移或授权设备。不要为“配置成功”删除旧文件。自定义 SSH 条件 `Match`（包括 `Include` 中的规则）不在当前自动配置范围内，发现就停止，不改动其他用户策略。

## 3. 建立常驻 Mac → VPS 通道

已有正确的反向隧道：跳过新建，直接到第 4 步验证。不能在相同 VPS 端口再建一条隧道。

新建时，在常驻 Mac 的项目目录执行：

```bash
python3 deploy/hermland.py relay-key
```

通过标准：打印公钥路径和 SHA256 指纹。私钥留在这台 Mac 的受限目录中；发送的只是 `identity.pub`。

把这份公钥通过可信渠道交给管理员。管理员核对来源和指纹，保存为 VPS `/root/mini.pub`，再在 VPS 执行：

```bash
bash /opt/hermland/ssh-relay.sh authorize /root/mini.pub
```

通过标准：打印 `PASS` 和相同指纹。`hl-relay` 只允许反向转发到 VPS `127.0.0.1:19119`，不能执行 Shell，不能使用它管理 VPS。

管理员通过已有可信 SSH 连接取出服务器公钥。在管理电脑执行：

```bash
ssh root@VPS_IP 'cat /etc/ssh/ssh_host_ed25519_key.pub' > vps-host.pub
```

把 `vps-host.pub` 通过可信渠道传到常驻 Mac 的项目目录。在常驻 Mac 执行：

```bash
python3 deploy/hermland.py relay-install --host VPS_IP --server-key ./vps-host.pub
```

OpenClaw 则只执行这一条：

```bash
python3 deploy/hermland.py relay-install --backend openclaw --host VPS_IP --server-key ./vps-host.pub
```

通过标准：首次安装时，真实 SSH 认证和反向转发探测通过，再登记 `land.hermland.onboarding-relay`。重复执行相同配置只复用服务，当前链路状态仍由下一步验证。服务器公钥错误、未经授权或端口冲突会停止，不接受“跳过身份校验”。

新安装使用 macOS 自带 `launchd + ssh` 自动恢复，不需要独立安装 autossh；已有 autossh 服务保持不变。

## 4. VPS：验证中转

在 VPS 执行：

```bash
python3 /opt/hermland/hermland.py check --port 19119
```

OpenClaw 则只执行：

```bash
python3 /opt/hermland/hermland.py check --backend openclaw --port 19119
```

通过标准：打印 `PASS`，中转只监听 `127.0.0.1:19119`，能通过隧道取得 WebUI 的健康响应。刚登记服务时可稍等再重跑；没有通过就不要继续授权客户端。

失败检查顺序：第 1 步后端 → 常驻 Mac 中转服务 → VPS 授权/端口。服务日志保留在常驻 Mac `~/Library/Application Support/HermlandRelay/`；不要把完整日志、`.env` 或私钥发到聊天。

## 5. 授权客户端，自动生成连接配置

在客户端打开 Hermland，点「复制设备公钥」。通过可信渠道交给管理员；不要把 App 私钥导出来。管理员确认这是要授权的电脑，保存公钥到 VPS `/root/device.pub`。

管理员在 VPS 执行；每台电脑使用不同设备名：

```bash
bash /opt/hermland/ssh-device.sh authorize hl-device0001 /root/device.pub
bash /opt/hermland/ssh-device.sh list
python3 /opt/hermland/hermland.py export --device hl-device0001 --host VPS_IP --output /opt/hermland/hl-device0001.json
```

OpenClaw 在相同的手动授权后，改用这条导出命令：

```bash
python3 /opt/hermland/hermland.py export --backend openclaw --device hl-device0001 --host VPS_IP --output /opt/hermland/hl-device0001.json
```

自定义路径再加 `--ui-path /实际路径`。文件名可保持不变，但不同配置不会覆盖已有文件；更新时使用新文件名并核对后导入。导出字段中的后端类型决定 App 使用哪种页面/健康检查，不能拿 Hermes JSON 去连接 OpenClaw。人工参考模板见 `deploy/connection.openclaw.example.json`，正常使用仍推荐自动导出。

通过标准：授权输出的指纹与 App 公钥一致，列表包含该设备，导出命令打印 `PASS`。配置包含服务器身份公钥，不包含私钥、密码或模型 API Key。导出不能代替授权，也不会自动批准设备。

管理员把 `hl-device0001.json` 发回用户。管理员可代你执行脚本，但必须先得到你对这台设备的明确确认；没有公网申请入口或自动审批。

## 6. 客户端：导入并验收

Hermland 点「导入连接配置」→ 核对文件来自管理员 →「连接」。在客户端终端执行：

```bash
python3 deploy/hermland.py check --port 19121
```

OpenClaw 则只执行：

```bash
python3 deploy/hermland.py check --backend openclaw --port 19121
```

通过标准：打印 `PASS`；App 能加载原界面。OpenClaw 在页面中完成原有 Gateway 登录，必要时按它的设备提示在常驻机人工处理；SSH 已手动授权不等于 Gateway 已登录。上游可能在回环连接、认证成功且具有浏览器设备身份时自动批准内层配对，我们不修改此规则，也不提供公网申请入口。最后由你发送一条消息得到真实模型回答。关闭 App 后本机端口关闭，再打开能自动建立 SSH；这才是完整使用验收。模型消息通常会产生少量费用，由你本人发送或明确授权 Agent 发送。

OpenClaw 的网页身份按可信 SSH 路由隔离保存，不和其他服务器共用。修改服务器公钥、后端路径或切换设备用户后可能需要重新登录/配对，不影响远端 Agent 的记忆和会话。这里只转发 Gateway；独立 portal 服务、跨源预览与系统通知不在本次适配范围。协议/页面特征按 OpenClaw 2026.9.9 验证，其他版本仍需实际验收。相关上游约束见 [Control UI](https://docs.openclaw.ai/web/control-ui)、[远程访问](https://docs.openclaw.ai/gateway/remote)、[健康检查](https://docs.openclaw.ai/gateway/health)。

换电脑要重新生成并授权公钥，不复制旧私钥。撤销命令见 [设备授权](安全门禁.md#撤销一台电脑)，会拒绝新连接并断开现有连接。

Agent 补齐 WebUI 前还应阅读上游 [Agent 配置检查清单](https://github.com/nesquena/hermes-webui/blob/master/docs/onboarding-agent-checklist.md)。主机命令是否可执行取决于现有工具权限与审批，不能只凭聊天入口就假定能配置 VPS；参见 [Hermes 工具与执行环境](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools/) 和 [OpenClaw 命令执行工具](https://docs.openclaw.ai/tools/exec)。本项目负责远程接入，不复制另一套模型配置系统。
