# 外网连接家里 Agent：怎么选

[简体中文](外网连接方案对比.md) · [English](外网连接方案对比.en.md)

只访问已有 Agent、已有可信 VPS、坚持人工登记设备公钥，Hermland 适合这条窄路径。没有 VPS、又希望少维护服务器，可以先考虑 Tailscale；需要浏览器即用，可以评估 Cloudflare Tunnel + Access，但要接受不同的信任边界。这是基于下表的选型建议，不是速度、安全等级或易用性排名。

| 方案 | 便利之处 | 需要承担什么 |
| --- | --- | --- |
| Hermland：双 SSH + 自有 VPS | 两端主动连接，不要求家庭公网 IP、路由器端口转发或域名；macOS 自带 SSH。人工登记每台设备公钥，只放行指定 Agent 中转端口；App 提供配置材料、导入与连接检查。 | 自己维护 VPS、SSH 和常驻 Mac；当前不是免部署方案。当前 HTTP 页面流量在 VPS 汇合，VPS 管理员有能力读取转发内容；不是客户端到家里的端到端加密。 |
| Tailscale | 协助建立直连，无法直连时使用加密中转，通常不必自行租 VPS。可以启用设备审批和端口限制，DERP 中转不能解密设备间流量。 | 两端安装客户端并管理组网账号与访问规则；依赖协调服务及网络可达性。审批和最小权限需要配置，不等于装好后自动收紧。当前 Hermland 不提供这种连接模式。[客户端初始化](https://tailscale.com/docs/how-to/quickstart)、[加密中转](https://tailscale.com/docs/reference/derp-servers)、[设备审批](https://tailscale.com/docs/features/access-control/device-management/device-approval)、[端口规则](https://tailscale.com/docs/features/access-control/grants)。 |
| 自建 WireGuard | 自己管理设备公钥和网络，不必使用托管组网账号；适合同时访问多个家庭服务。 | 需要配置客户端、可达节点、路由、防火墙和密钥撤销。加密范围取决于终止点：若 VPS 作为终止两段隧道的路由中心，它仍可读取未另做应用层端到端加密的内容，不能一概称为“中转不可解密”。[官方配置与 NAT 说明](https://www.wireguard.com/quickstart/)。 |
| Cloudflare Tunnel + Access（发布 Web 应用） | 家里运行 `cloudflared` 主动连出，无需家庭公网 IP；浏览器入口可配登录规则，不必自管传统 VPS。 | 通常需要域名、Cloudflare 账号、隧道与 Access 规则。普通账号登录不等于只准特定电脑；设备限制需额外策略。HTTP 代理在 Cloudflare 终止 TLS，因此需要信任它处理请求内容；Agent 登录、WebSocket 和设备配对仍需实测。[隧道](https://developers.cloudflare.com/tunnel/)、[Access 策略](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/)、[两段 TLS](https://developers.cloudflare.com/ssl/get-started/)。 |
| 直接 SSH 到家里 | 没有应用流量中转服务器，按设备公钥认证，再用 SSH 转发原网页端口。 | 家里的 SSH 服务必须从外网可达；可能需要公网 IPv4/IPv6、路由器转发及防火墙配置，并维护公网 SSH。只公开 SSH，不把 Agent WebUI 裸露到公网。当前 Hermland 不提供这个配置模式。[OpenSSH 加密与端口转发](https://man.openbsd.org/ssh.1)。 |
| frp | 通用内网穿透，可转发多种服务；STCP 能避免把目标端口直接开放到公网。 | 需要维护服务端、客户端和访问规则。STCP 的访问端还要运行客户端，并持有相同共享密钥；共享密钥不等于每台设备独立公钥。隧道连通也不代替 Agent 登录和设备权限管理。[STCP 官方说明](https://gofrp.org/en/docs/features/stcp-sudp/)。 |

所有方案都要求家里的 Agent 在线。Apple 签名、公证解决的是“下载的 App 来自谁、是否被篡改以及是否通过 Apple 扫描”，不代替连接授权，也不保证模型可用。[Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。端口连通后仍应保留原 Agent 登录，检查设备、服务器身份和真实模型回答。

以上替代方案没有作为 Hermland 模式做过验收，不承诺具体地区的速度或可用性。选择后端与网络方案时，应用登录、WebSocket、设备撤销和断线恢复应分别验证。资料核对日期：2026-10-13。
