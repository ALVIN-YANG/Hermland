# 项目背景

Hermland 面向已经在使用 Hermes 或 OpenClaw 的用户，解决从另一台 Mac 安全访问自己的常驻 Agent 的问题。不是新的 Agent，不保存另一份模型配置，不迁移已有记忆和会话。

## 当前范围

- macOS 14+ 客户端。
- 常驻 macOS 上已有 Hermes + 社区 Hermes WebUI，或 OpenClaw Gateway + Control UI。
- 用户自己的 Debian/Ubuntu VPS，仅提供受限 SSH 中转。
- 手动设备公钥授权；没有主动申请、自动审批或共享令牌。

用户可把初始化指令发给自己的已有 Agent，或者按同一套脚本手动配置。没有执行权限、兼容性或人工确认时停在当前步骤，不扩大权限。

## 设计取舍

保持薄客户端，复用上游 UI，而不是重复实现会话、登录、模型和工具。Hermes 与 OpenClaw 使用各自健康接口和网页协议，不假设两者 API 相同。

使用系统 SSH、固定服务器公钥与独立设备密钥，不发明新的认证协议。反向隧道避免要求家庭网络开放入站端口；代价是需要用户自己的可信 VPS。两段 SSH 不提供客户端到常驻 Mac 的端到端加密，VPS 管理员是信任边界的一部分。

网页身份按可信 SSH 路由隔离，避免同一个回环端口切换后串用另一台服务器的凭据。内层登录和真实模型回答由用户在原页面验收，不能用网络存活代替。

## 开源目标

陌生用户不依赖维护者现场协助，也能理解、配置、检查、撤销和维护自己的接入。先做好这个完整路径，再考虑其他平台或复杂管理界面。

当前是开发预览；正式签名、公证、独立用户及跨网络验收未完成。验收边界见 [发布与验收](发布与验收.md)。
