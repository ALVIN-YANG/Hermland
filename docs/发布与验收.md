# 发布与验收

## 当前阶段

0.1.0-preview.1 是可下载的公开预览，不是 Developer ID 签名、公证的正式版。支持 macOS 14+ 客户端、常驻 macOS、Debian/Ubuntu 的 `ssh.service`。OpenClaw 协议按 2026.9.9 验证，其他版本需实测；Hermes 使用社区 WebUI，不把它当成 Hermes 官方 Desktop 协议。每次发布应记录实际验收的上游版本/提交。

## 构建与打包

```bash
bash scripts/check.sh --macos
bash scripts/package-macos.sh --development
```

输出 `releases/Hermland-版本-dev.zip`、`HermlandSetup-版本-dev.zip`、SHA256 校验值与 `BUILD-版本-dev.json` 构建来源。App 含 Apple Silicon 和 Intel 两种架构。临时签名、未公证的包可以作为公开预览分发，但必须标注限制。用户是否信任这个 App 由本人决定，不全局关闭 Gatekeeper。现有钥匙串设备密钥不会主动替换，签名变化可能触发访问确认，由用户本人处理。

公开预览须来自干净的提交；先等待该提交 CI 全部通过，再打包、核对架构/签名/资源，创建指向同一提交的 `v版本-preview.N` 标签，发布为 GitHub prerelease，并附构建来源与校验值。下载页通过 GitHub Pages 托管，下载文件只指向本仓库的 Release；网站不接收公钥、凭据、连接申请或聊天。

正式打包只接受 Developer ID Application 证书和用户已经登记的 notarytool 钥匙串配置：

```bash
HERMLAND_SIGN_IDENTITY='Developer ID Application: 你的证书名' \
HERMLAND_NOTARY_PROFILE='你已登记的公证配置名' \
bash scripts/package-macos.sh --signed
```

正式入口要求干净的已提交源码、Hardened Runtime、时间戳签名、公证状态 `Accepted`、staple 与 Gatekeeper 评估通过。任一项失败就不生成正式包；不在脚本、GitHub 或聊天中填写 Apple 密码。当前没有可用 Developer ID 证书，这个入口尚未完成真实公证验收。

CI 对 PR 只提供读权限，不使用生产钥匙。Linux 检查与 Ubuntu/Debian 真 SSH 验收分开；macOS 跑适配、指引与资源打包测试，再构建清楚标注的开发预览。CI artifact 不是 GitHub 正式 Release。

## 已部署工具的升级

默认 `setup-vps.sh` 拒绝覆盖不同版本。管理员应核对本次差异，并在新的部署目录中执行 `bash deploy/setup-vps.sh --upgrade`；原四个工具保存在 `/opt/hermland/backups/时间-PID/`，不会迁移密钥、自动授权或修改后端。不能为重跑安装直接删除旧目录。

旧授权记录没有公钥级命令限制。升级工具后，用当初人工核对过的原公钥再次执行 `authorize`，不会自动授权不同公钥。新导出工具拒绝旧授权记录，直到管理员完成这一步。旧 App JSON 仍能读取；本项目不会自行改动已有生产 VPS。

## 独立用户验收

邀请 3–5 位已有 Hermes/OpenClaw 的用户，使用自己的常驻 Mac 和测试 VPS。至少分别覆盖两个后端；不要共享维护者的账号或密钥。记录安装包版本、OS、上游版本、完成时间、失败步骤与求助次数，不收集凭据或聊天。

| 项目 | 通过证据 |
|---|---|
| 初次配置 | 用户自行通过 Agent 或手动步骤，导入配置并打开自己的原会话 |
| 身份拒绝 | 未授权设备、错误服务器公钥都被拒绝，不跳过校验 |
| 实际使用 | 用户本人发一条消息并收到真实模型回答 |
| 恢复 | 断网/恢复、睡眠/唤醒、重开 App 后检查连接与会话 |
| 撤销 | 指定设备现有连接关闭，新连接被拒绝，其他设备和中转不受影响 |
| 升级 | 从上个包升级后，原设备公钥不变，配置和网页身份按既定路由保留 |
| 运维 | 常驻 Mac 重启并登录、VPS 重启后链路恢复，失败可定位并处理 |

容器测试不能代替以上真实设备和跨网络证据。没有这些记录前，不宣称“高价值已验证”“普通用户开箱即用”或“安全审计通过”。
