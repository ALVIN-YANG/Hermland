# 双 SSH 远程中转

两条端口隧道传输 HTTP 与 WebSocket 数据，SSH 不负责生成网页。界面由常驻 Mac 的 Hermes WebUI 或 OpenClaw Control UI 提供。

客户端 App 用本机独立设备密钥连接 VPS，并只转发到 VPS 回环中转端口。常驻 Mac 主动连接 VPS，把后端回环端口发布到同一个中转端口；家庭路由器不需要开入站端口。

默认端口：

| 位置 | 地址 | 用途 |
|---|---|---|
| 客户端 | 127.0.0.1:19121 | App 管理的本地转发 |
| VPS | SSH :22 | 公钥认证入口 |
| VPS | 127.0.0.1:19119 | 两条 SSH 隧道交会的中转端口 |
| 常驻 Mac | 127.0.0.1:8787 | Hermes WebUI |
| 常驻 Mac | 127.0.0.1:18789 | OpenClaw Gateway / Control UI |

## 常驻 Mac

新安装使用 macOS 自带 `launchd + ssh`，专用中转账户为 `hl-relay`。登录后启动，断线会重试；需要用户保持登录、机器不睡眠且网络可用。不要求安装 autossh。

已有正确的 autossh 或其他反向隧道可先复用，不自动迁移；不要让两条服务同时占用同一 VPS 端口。新配置必须显式绑定 VPS 回环地址，不能绑定 0.0.0.0。按 [快速开始](快速开始.md) 每步检查。

## VPS

仅开放已有 SSH 入口，不公开 WebUI 或中转 HTTP 端口。设备与中转分别使用受限专用账户，不复用管理员密钥。

不需要域名或 HTTPS 证书。直接使用 VPS IP 时，身份仍由管理员提供的完整 SSH 主机公钥验证。旧 Gate 或公开反代不是当前方案，历史部署升级时由管理员确认停用。

## 客户端

App 自动建立系统 SSH 的本地转发，固定主机公钥，禁止密码回退和 SSH agent，忽略用户个人 SSH 配置。公钥未经授权或服务器身份不符时停止，不回退公网 HTTPS。

连接分四项检查：配置格式、本机密钥、实际 SSH 授权与服务器身份、后端健康接口。SSH 意外中断后最多重试三次；失败返回配置页。页面进程异常会有限次尝试恢复，可手动刷新和复制检查结果。

Hermes 使用 /health；OpenClaw 使用 /healthz 的 ok=true,status=live，并确认 Control UI 页面特征。自定义 Control UI 路径须与导出 JSON 一致。网页身份按可信 SSH 路由隔离；不转发 OpenClaw 独立 portal 服务或承诺原生通知。

## 必须分别验收的结果

健康接口通过说明链路与对应服务可达，不说明网页已登录、模型可用或桌面工具权限已齐。用户还须在原页面完成登录，并本人发送一条消息确认真实回答。

VPS 管理员能访问中转内容；其他本机程序能访问当前打开的回环端口。因此客户端、常驻 Mac、VPS 都必须可信。此方案控制远程准入，不提供应用内多租户分权。
