# 设备公钥授权（双 SSH 通道）

现在不再用共享 Gate 令牌登录。每台电脑各有一对 Ed25519 密钥：公钥可以交给管理员，私钥保存在本机钥匙串。知道服务器地址或公钥，不等于获得访问权限；连接者还必须证明持有已授权公钥对应的私钥。

```text
Mac 上的 App
  └─ 专用设备密钥 → VPS SSH：固定校验服务器公钥
       └─ 只允许访问 127.0.0.1:19119
            └─ Mini 已有的 SSH 反向隧道 → Mini 127.0.0.1:8787
```

## 新电脑的配置

1. 打开 App，点「复制设备公钥」，通过可信渠道发送给管理员。
2. 管理员在 VPS 上给该公钥创建一个独立设备用户。
3. 管理员运行配置导出命令后发回连接 JSON，其中包含 VPS 地址、设备用户和完整服务器公钥。它不包含私钥、密码或 Gate 令牌。
4. 在 App 中「导入连接配置」，核对来源后点「连接」。首次成功后自动保存配置，后续打开自动连接。

SSH 准入没有设备主动申请接口，没有自动审批，也不会首次连接时盲目信任服务器。服务器公钥错误时必须停止连接，向管理员核对；不要跳过校验。

OpenClaw 复用相同的 SSH 准入，Mini 最后一跳默认换成 `127.0.0.1:18789`。连接 JSON 的 `backend` 为 `openclaw`，可包含自定义 `controlUIPath`，不包含 Gateway 令牌。内层仍保留 OpenClaw 的 token/password、浏览器设备身份与配对规则。它可能将转发连接视为回环，在 Gateway 认证成功后自动批准内层浏览器身份；这不是自动授权一台远程电脑的 SSH 公钥，也不是免令牌登录。不要用 `auth.mode: none` 或 `dangerouslyDisableDeviceAuth` 简化配置。

## 管理员如何授权

在 VPS 上安装 `deploy/ssh-device.sh` 到 `/opt/hermland/ssh-device.sh`，以 root 运行。脚本假设 VPS 使用 OpenSSH、systemd 和 `ssh.service`；每次修改后先执行 `sshd -t`，成功才重载服务。

```bash
# device.pub 是用户发送来的单个 Ed25519 公钥
bash /opt/hermland/ssh-device.sh authorize hl-device0001 /path/to/device.pub 19119
bash /opt/hermland/ssh-device.sh list
```

设备名为 `hl-` 加 8–24 位小写字母或数字，每台电脑一个名。脚本拒绝覆盖其他用途的账户，也拒绝直接替换已有的不同公钥。授权文件在 `/etc/hermland/ssh-devices/设备名.pub`，由 root 管理，设备自己不能修改。

服务器公钥从**已验证的管理 SSH 连接**或服务器控制台获取：

```bash
cat /etc/ssh/ssh_host_ed25519_key.pub
```

把其中的 `ssh-ed25519 AAAA…` 填入 JSON 的 `serverPublicKey`。不能只填 SHA256 指纹，不能拿未经核对的 `ssh-keyscan` 结果当可信来源。管理员可在家里的 Mini 或另一台持有管理 SSH 密钥的电脑上执行这些命令。当前没有管理 GUI；App 连接页负责导入配置和复制公钥。

新流程不需要手工填写 JSON。在 VPS 上安装管理工具后执行：

```bash
python3 /opt/hermland/hermland.py export --device hl-device0001 --host VPS_IP --output /opt/hermland/hl-device0001.json
```

导出会核对已有公钥授权和实际 SSH 策略，使用本机服务器公钥；不会自动授权设备。完整分步流程和可复制的 Agent 指令见 [快速开始](快速开始.md)。配置模板仍保留供人工参考。

## 撤销一台电脑

```bash
bash /opt/hermland/ssh-device.sh revoke hl-device0001
```

撤销会移走该设备授权公钥，并终止这个专用用户的现有 SSH 连接。不影响其他设备或 Mini 反向隧道。授权记录保留为 `.revoked-时间` 文件，便于审计或恢复。换电脑使用新公钥，旧电脑不再使用时单独撤销；不要把旧电脑的私钥复制过去。

## 日常与边界

- App 连接成功后打开本机 `http://127.0.0.1:19121/`，网络传输由两段 SSH 加密。SSH 准入不阻止其他本机程序访问这个端口；它不是局域网或公网监听。OpenClaw 的 Gateway 认证仍独立校验，不把 HTTP 存活当成已登录。
- Hermes 的「在浏览器打开」也打开这个本机地址。必须保持 App 和 SSH 隧道运行；断开后浏览器不能继续访问。不再签发 180 天 Gate Cookie。OpenClaw 仅在 App 的路由隔离 WebKit 存储中打开，避免普通浏览器在相同回环地址复用另一台 Gateway 的凭据。
- VPS 设备账户仅允许本地转发到指定端口，禁止 Shell、PTY、代理转发、反向转发和 Unix Socket 转发。与管理员 SSH 账户分开。
- 临时 SSH 私钥文件位于权限 `700` 的目录，文件权限 `600`；连接结束时清理。App 异常退出后，监督进程也会关闭 SSH 并清理临时文件。
- SSH 中断后自动重试 3 次；仍失败则显示连接页，不回退公网 HTTPS。
- 当前是临时签名的开发构建。重编译后，macOS 可能要求你重新确认 Hermland 访问钥匙串；由你本人处理系统提示，不关闭钥匙串保护。正式发行需要稳定代码签名。
- 两段 SSH 不等于 App 到 Mini 的端到端加密：VPS 是可信中转点，VPS 管理员有能力访问转发内容。Mini、VPS 和已授权电脑都必须可信。私钥被盗仍可能被冒用，需要撤销对应设备。
- 不自动迁移已有反向隧道及其账户。新安装使用非 root 的 `hl-relay`；历史 root 隧道须由管理员单独评估和迁移。

旧 Gate 不属于当前发行方案。升级历史部署时，管理员必须确认旧公网 WebUI、取票和解锁代理已停用；不要重新启用旧 Gate 服务，它会绕过设备 SSH 准入。历史文件只留作本机回滚参考，不作为当前安装步骤。
